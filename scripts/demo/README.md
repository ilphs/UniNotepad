# Markdown 프리뷰 데모 영상 — 촬영 파이프라인

랜딩 페이지 히어로의 lead shot을 "타이핑 → 프리뷰가 따라옴" 영상으로 바꾸기 위한
촬영 도구 모음. v1은 2026-08-11에 촬영·반영 완료. **v2는 촬영 대기 중이다** —
아래 검증 체크리스트를 통과하기 전에는 산출물을 `site/assets/`에 넣지 말 것.

## 파일

| 파일 | 역할 |
|---|---|
| `seed-session.sh` | 격리 HOME + `session.json` 씨딩 → **평문(Normal)** 빈 Untitled 탭 |
| `type.applescript` | 텍스트 파일을 사람 속도로 한 글자씩 타이핑 |
| `click.js` | JXA+CGEvent 클릭 (상태바 칩·픽커 항목 — WebView 내부라 AX로는 안 됨) |
| `probe-picker.sh` | 픽커 팝업 좌표 실측용 스냅샷 (녹화 없음, 최초 1회) |
| `probe-focus.sh` | 단계별 최상위 앱·창 좌표·스냅샷 진단 (촬영이 이상할 때) |
| `steps/00-warmup.txt` | Mermaid lazy import 워밍업용 (영상에 안 들어감) |
| `steps/0{1,2}-*.txt` | 산문 원고 2단락 |
| `steps/03-mermaid-open.txt` | 펜스 + `flowchart LR` (디바운스보다 빠르게 쳐서 빈 다이어그램 렌더를 건너뛴다) |
| `steps/04-mermaid-body.txt` | 다이어그램 본문 (줄마다 렌더되며 자라난다) |
| `record.sh` | 가드 → 실행 → **리허설 검증** → 녹화 → 트림/인코딩 |

## 실행

```bash
npm run tauri build              # 릴리즈 바이너리 필요
./scripts/demo/probe-picker.sh   # 최초 1회 — 팝업을 찍어 MENU_* 좌표 실측
# out/probe/02-picker.png 에서 "Markdown"/"Normal" 행 y를 재어 record.sh 상단에 채운다
./scripts/demo/record.sh
```

산출물은 `scripts/demo/out/` 에 떨어진다. 눈으로 확인한 뒤 직접 복사한다.

> **권한**: 두 스크립트 모두 **명령을 띄운 터미널 앱**에 *화면 기록* + *손쉬운 사용*
> 권한이 있어야 한다. 권한은 셸이 아니라 프런트 앱에 붙으므로 터미널을 바꾸면 다시
> 부여해야 한다 — iTerm2에서는 되던 것이 다른 터미널에서는 `osascript ... -1719`
> (보조 접근 불허)로 죽는다. 권한을 새로 준 뒤에는 그 앱을 재시작해야 적용된다.

## 왜 이렇게 만들었나

**v1: 프리뷰를 세션으로 열었다.** 프리뷰 분할 상태는 탭별로 `session.json`에 저장된다
(`src/session.ts:85-89, 170-176`). 격리 HOME에 미리 써 두면 녹화 중 `Cmd+Shift+M`을
누를 필요가 없었다 — "CM6가 네이티브 accelerator를 가로챔" 제약을 우회하는 방법이었다.

**v2: 픽커 조작 자체가 시나리오가 됐다.** 파일타입을 Markdown으로 고르면 프리뷰가
열리므로(`src/tabs.ts:300-303`) 씨딩은 평문 상태로 되돌리고, 상태바 픽커를 실제로
클릭한다. **편집창 토글은 클릭 말고는 경로가 없다** — 네이티브 메뉴에도 `main.ts`
accelTable에도 없고, `toggleEditorPane`을 부르는 곳은 창의 × 버튼과 상태바
`Editor NNN%` 칩뿐이다(`statusbar.ts:152-158`, `preview.ts:670`). 그래서 클릭
자동화가 v2의 전제 조건이고, JXA+CGEvent(`click.js`)로 해결한다.

**클릭 좌표는 계산하지 않고 실측한다.** 픽커 팝업은 상태바 위에 **바닥 기준**으로
붙는다(`openPicker`: `top = anchor.top - menuHeight - 4`). 항목이 17개라 항목 높이를
1px만 잘못 잡아도 팝업 전체가 17px 밀린다 — "Markdown"(위에서 두 번째) 좌표를
계산으로 맞추면 ±30px 오차가 난다. `probe-picker.sh`로 한 번 찍어 재는 편이 싸다.
상태바 칩은 오른쪽 정렬이라 **텍스트 오른쪽 끝이 고정**이고 라벨이 짧아지면 왼쪽 끝만
움직인다 — `Editor 107%`/`Editor off` 양쪽에 들어오는 x를 잡으면 한 좌표로 토글을
껐다 켤 수 있다.

**녹화 전에 리허설로 전 구간을 검증한다.** 클릭이 한 번 빗나가면 1분을 버리고도
"아무 일도 안 일어나는 영상"이 남는다. `record.sh`는 녹화 없이 픽커→Markdown→
워밍업→편집창 토글을 한 번 돌리며 매 단계 화면이 실제로 바뀌었는지 픽셀 차이로
확인하고(ffmpeg `blend=difference` + `signalstats`), 마지막에 평문 상태로 되돌린 뒤
녹화를 시작한다. 어긋나면 촬영을 시작조차 하지 않는다.

**검증 캡처 자체를 먼저 의심해야 한다.** `screencapture` 정지 캡처는 간헐적으로
**창을 제외한 바탕화면만** 돌려준다. 2026-08-11 촬영에서 이것 때문에 한참을 헤맸다 —
AX는 창이 (60,60) 1400×900에 그대로 있다고 보고했고, 같은 시각 `screencapture -v`
영상에는 창이 정상적으로 찍혔다. 즉 창이 사라진 게 아니라 정지 캡처만 틀렸다.
그래서 `shot()`은 매 캡처마다 타이틀바 **밝기**를 확인하고(창=어두움 ~72, 벽지=~200)
어긋나면 다시 찍는다. 밝기로 판정하는 이유는 픽셀 비교가 못 쓰기 때문이다 — 문서가
수정되는 순간 제목 앞에 수정됨 표시(●)가 붙어 픽셀이 크게 달라진다(이걸로 한 번
오판해서 촬영이 중단됐다).

**판정 영역은 "가장 크게 바뀌는 곳"으로 잡는다.** mermaid 다이어그램은 프리뷰
면적의 3%뿐이고 노드 채움색이 배경과 비슷해 평균 차이가 0.55밖에 안 나온다 —
프리뷰로 "타이핑이 들어갔는지"를 판정하면 멀쩡한 촬영이 중단된다. 타이핑은 편집창
영역으로, 편집창 토글도 편집창 영역으로 본다(소스 텍스트 ↔ 프리뷰 배경).

**상태바를 누르기 전에 편집기 포커스를 뗀다.** 편집기에 포커스가 있는 동안 상태바
칩을 누르면 **첫 클릭이 blur로 소모되어** 칩의 click 핸들러까지 가지 않는다. 촬영
로그가 이것을 그대로 보여줬다 — 편집기 포커스 상태에서 누른 "픽커 열기"·"편집창
닫기"는 두 번째 클릭에 반응했고, 포커스가 이미 빠져 있던 "Markdown 선택"·"편집창
다시 열기"는 한 번에 반응했다. 클릭 핸들러가 없는 탭 바 빈자리를 먼저 눌러 그 몫을
소모시키면 모든 클릭이 한 번에 먹고, 재클릭을 기다리던 2초짜리 정지 화면도 사라진다
(41.4초 → 38.6초).

**원고는 중간 상태까지 유효한 mermaid여야 한다.** 프리뷰는 펜스가 닫히기 전에도
mermaid로 렌더를 시도하므로, 타이핑 도중의 불완전한 소스가 그대로 **빨간 파싱 오류
박스**로 몇 초씩 노출된다. 1차 v2 촬영에서 `subgraph Autosave` … `end` 사이 구간과
펜스만 연 시작 순간이 정확히 그렇게 찍혔다. 대책 두 가지:

- **`subgraph`를 쓰지 않는다.** 줄 단위로 끊어 봐도 모든 접두사가 유효한 문법이면
  오류가 아예 안 뜬다(플로우차트 엣지 나열은 이 성질을 만족한다).
- **펜스와 `flowchart LR`은 디바운스(200ms)보다 빠르게 친다.** 내용 없는 상태로
  렌더되면 "No diagram type detected" 오류가 뜬다. 두 줄을 한 스텝으로 떼어 내
  `LINE_DELAY=0.12`로 치면 그 사이에는 렌더가 아예 일어나지 않는다.

**원고가 에디터 동작을 피해 간다.** `src/editor.ts:173-190` 확인 결과:

- `closeBrackets()` 활성 — `[`는 `[]`로 자동 페어링되지만 닫는 문자를 이어서 치면
  skip-over 되므로 소스를 그대로 쳐도 결과가 맞는다. 원고의 `[`, `(`는 짝을 이룬다.
  (1차 촬영에서 `- [x]`가 그대로 찍히는 것으로 확인됨.)
- **줄바꿈은 Shift+Return으로 보낸다.** `markdown()`은 `addKeymap` 기본값이 true라
  `Prec.high`로 Enter → `insertNewlineContinueMarkup`을 심는다
  (`node_modules/@codemirror/lang-markdown/dist/index.js:396-422`). `editor.ts`의
  keymap 배열에는 안 보이지만 실제로는 `defaultKeymap`을 이긴다. 그냥 Return을 쓰면
  `- [x] ...` 다음 줄에 `- [ ] `가 자동 삽입돼 원고와 겹치고(`- [ ] - [x] ...`),
  빈 리스트 항목에서 Enter가 마커를 지우느라 빈 줄 하나가 먹힌다 — 1차 촬영이 그렇게
  깨졌다. `markdownKeymap`은 `Enter`만 바인딩하므로 Shift+Return은 `defaultKeymap`의
  `insertNewlineAndIndent`로 빠져 원고를 글자 그대로 입력한다.
- 펜스 안 들여쓰기는 실제로 붙지 않았다. 붙더라도 mermaid는 선행 공백을 허용한다.

**Mermaid를 워밍업한다.** mermaid는 최초 사용 시 lazy import 된다
(`src/preview.ts:146-157`). 워밍업 없이 찍으면 영상의 클라이맥스 직전에 번들 로딩
멈칫이 그대로 들어간다.

**줄바꿈 지연은 프리뷰 디바운스보다 커야 한다.** `schedulePreviewRender`는 키 입력마다
200ms 타이머를 리셋한다(`src/preview.ts:365-374`). 글자 간격이 200ms 아래로 이어지면
타이핑 중에는 프리뷰가 **한 번도 그려지지 않고** 쉼에서만 뭉텅이로 따라온다 — 1차
촬영이 그랬다(10초 시점까지 리스트가 프리뷰에 전혀 없었다). `LINE_DELAY=0.5`로
줄마다 디바운스를 통과시켜 줄 단위로 따라오게 만든다.

## 스토리보드 (v2, 실측 38.5초)

v1(~22초)에서 세 가지가 바뀌었다: **파일타입을 고르는 오프닝**, **더 큰 Mermaid**,
**편집창을 닫았다 여는 마무리**. 클라이맥스는 여전히 Mermaid이고, 편집창을 닫아
다이어그램이 전체 폭으로 커지는 장면이 그 뒤를 받는다.

| 구간 | 내용 | 대략 |
|---|---|---|
| 0–2s | 평문 빈 Untitled, 편집기 전체 폭 (프리뷰 없음) | 상태바 `Normal` |
| 2–5s | 상태바 파일타입 칩 클릭 → 픽커에서 `Markdown` 선택 | 프리뷰 창이 열린다 |
| 5–10s | `# UniNotepad` / `Type on the left. It renders on the right.` | H1과 문단이 오른쪽에 뜬다 |
| 10–17s | 체크박스 3줄 | GFM task list 렌더 |
| 17–31s | ```` ```mermaid ```` 8노드 다이어그램 (분기 → 합류 → DB/서브루틴 노드) | **줄마다 자라난다** |
| 31–36s | `Editor` 칩 클릭 → 편집창이 닫히고 프리뷰가 전체 폭 | 넓은 다이어그램이 커진다 |
| 36–38.5s | `Editor off` 칩 클릭 → 편집창 복귀, 정지 | 마지막 프레임 = poster |

원고는 **영어 1벌만** 만든다. 언어별 촬영은 제작·용량이 2배가 되는데 얻는 게 없다.
캡션만 `index.html` / `ko.html`에서 각각 쓴다.

## 검증 체크리스트 (전부 통과해야 사이트 반영)

1. ~~**가드 1** — 시작 시 실행 중인 UniNotepad가 있으면 중단되는가.~~ **검증 완료**
   (2026-08-11): 설치본이 실행 중인 상태에서 실행해 PID를 출력하고 exit 1로 막히는 것을
   확인했다. 과거 이 가드를 빌드 경로로 좁혔다가 두 번 사고가 났다(사용자의 미저장 탭이 촬영됨).
2. ~~**가드 2** — 창 제목에 `Untitled`가 없으면 중단되는가.~~ **검증 완료** (v1 촬영).
3. ~~**격리** — 창이 1400×900으로 뜨는가.~~ **검증 완료** (v1 촬영).
4. **테마** — 첫 프레임이 다크인가. `theme.ts` 기본값을 믿지 말고 눈으로 볼 것.
5. **오프닝(v2)** — 픽커가 실제로 열리고 `Markdown`이 선택돼 프리뷰가 등장하는가.
   (리허설의 `assert_changed`가 1차로 막지만, 영상에서 팝업이 보이는지는 눈으로 볼 것.)
6. **타이핑 결과** — 영상 안의 소스가 `steps/*.txt`와 글자 단위로 같은가.
   특히 `[x]` 대괄호 중복, `[(…)]`·`[[…]]` 중첩 괄호, mermaid 펜스 백틱 개수, 들여쓰기 누적.
7. **Mermaid** — 다이어그램이 멈칫 없이 그려지는가(워밍업이 먹었는가).
   v2 원고는 노드 파서로 사전 검증하지 못했다(`mermaid.parse`가 DOM에 의존해 node에서
   `DOMPurify.addHook` 오류로 죽는다) — **렌더 결과가 유일한 검증**이다. 분기 라벨,
   `subgraph Autosave` 박스, `[(session.json)]` 실린더, `[[backups]]` 서브루틴 모양이
   전부 나오는지 확인할 것.
8. **편집창 토글(v2)** — 편집창이 닫히며 프리뷰가 전체 폭이 되고 다이어그램이 커지는가,
   그리고 다시 열리는가. 마지막 프레임이 분할 화면인가(= poster).
9. **툴팁** — 칩 위에 포인터가 머물러 `Click to close this pane` 툴팁이 뜬 프레임이 없는가
   (`click.js`의 park 좌표가 먹었는지).
10. **산출물** — mp4가 1400×900 / 2MB 이하 / 오디오 트랙 없음.
11. **육안 확인** — 사용자의 실제 파일명·문서가 한 프레임도 들어가지 않았는가.

## 사이트 반영 (검증 통과 후)

`site/index.html:79-82` 와 `site/ko.html:75-78` 의 lead shot `figure` 하나만 교체한다.
스텝 탭·크로스페이드는 넣지 않는다 — 영상이 1개면 오버엔지니어링이다.

```html
<figure class="lead-shot">
  <video
    src="/assets/md-preview-v2.mp4"
    poster="/assets/md-preview-v2-poster.jpg"
    preload="auto" autoplay loop muted playsinline controls
    aria-label="Typing Markdown in UniNotepad while the preview pane renders it live"
  ></video>
  <figcaption><b>Dark</b> theme — type on the left, rendered on the right</figcaption>
</figure>
```

`site/assets/site.css` 에 한 줄 추가 — 기존 규칙이 `.hero .shot img`만 잡는다:

```css
.hero .shot video { width: 100%; display: block; border-radius: var(--radius); border: 3px solid var(--border); box-shadow: var(--shadow-lg); }
```

주의:

- **캐시** — `?v=` 규칙은 css/js에만 있다. 영상은 파일명에 버전을 박는다
  (`md-preview-v1.mp4` → `md-preview-v2.mp4`). 재촬영하면 번호를 올리고 두 HTML을
  함께 고친다. 구버전 파일은 교체 커밋에서 지운다(`.git`가 불필요하게 불어난다).
- **CSS·JS를 고쳤으면** 두 HTML의 `?v=` 숫자를 함께 올린다(Vercel 엣지 캐시).
- **자동재생 중이다** (2026-08-11 사용자 요청). `muted` 없이는 어느 브라우저도
  자동재생을 허용하지 않으니 절대 떼지 말 것. `autoplay`/`loop`을 JS가 아니라 HTML에
  두는 이유는 JS가 죽어도 재생은 되게 하려는 것이고, `site.js`의 "히어로 데모 영상"
  블록이 두 가지를 얹는다 — 동작 최소화(`prefers-reduced-motion`)면 `load()`로
  poster를 되살려 정지, 화면 밖으로 나가면 일시정지.
  - **`controls`를 떼지 말 것.** 5초를 넘겨 자동 반복하는 콘텐츠에는 멈출 수단이
    있어야 한다(WCAG 2.2.2). v1은 21.9초, v2는 ~33초 루프다.
  - 동작 최소화에서 `pause()`만 하면 **거의 빈 편집기에서 얼어붙는다** — 재생이
    한 번 시작되면 poster가 다시 나오지 않기 때문이다. 마지막 프레임으로 seek하는
    방법은 디코딩에 기대야 해서 헤드리스 검증에서 실패했다. `load()`가 확실하다.
  - 참고로 marimo는 `autoplay`/`loop`을 쓰지 않고 JS로 선택된 스텝만 재생한다.
- **poster는 마지막 프레임**이다. 기존 `syntax-markdown.png`를 poster로 재활용하지
  말 것 — 정지 이미지(가득 찬 문서)와 영상 첫 프레임(빈 에디터)이 어긋나 재생 순간
  내용이 사라지는 것처럼 보인다.
- **`.git`는 현재 19MB, LFS 미사용.** 재촬영본을 커밋할 때마다 히스토리에 누적되고
  되돌릴 수 없다. 커밋 전에 영상이 확정됐는지 확인할 것.
